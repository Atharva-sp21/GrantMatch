ROOT CAUSES: Why GNN Hit Rate is 6.65% Despite Learning (Loss: 0.465→0.357)
================================================================================

SEVERITY: CRITICAL - Multiple fundamental issues preventing model from learning
          meaningful patterns despite loss decreasing.

================================================================================
ROOT CAUSE #1: FEATURE ENGINEERING IS BROKEN [IMPACT: +35-40%]
================================================================================

RESEARCHER FEATURES (claimed 9 dims, but useless):
  Problem: 52.1% of researchers have h_index=0 (521/1000)
           -> Completely indistinguishable in feature space
           -> Model can't learn to differentiate similar researchers
  Problem: Dims 6-9 are just normalized versions of dims 1-4
           -> Redundant/not adding information
  Problem: NO TOPIC INFORMATION despite 2,023 researcher-topic edges available
           -> Model doesn't know researcher specialties

GRANT FEATURES (claimed 7 dims, but mostly hardcoded):
  Problem: Features 2,3,4,5,7 are HARDCODED CONSTANTS
           -> Feature 2: always 1.0 (grant availability flag)
           -> Feature 3: always 1.0 (open - hardcoded)
           -> Feature 4: always 2.0 (career stage - neutral)
           -> Feature 5: always 0.5 (relevance - placeholder)
           -> Feature 7: always 1.0 (has title - all grants have titles)
  Problem: Only feature 1 and 6 vary (both are amount in different scales)
           -> All grants look nearly identical
           -> 100 unique amounts out of 200 grants
  Problem: NO TOPIC INFORMATION despite 303 grant-topic edges available
           -> Grant "Quantum Machine Learning" looks same as "Climate Change"
           -> Model can't match based on topic alignment

RESULT: Researchers indistinguishable, grants indistinguishable
        -> Model learns from noise, not meaningful patterns
        -> Despite loss decreasing, predictions are random

================================================================================
ROOT CAUSE #2: GRAPH STRUCTURE ENABLES 64% DISCONNECTION [IMPACT: +5-10%]
================================================================================

SEVERE SPARSITY:
  - Only 3,280 positive edges out of 200,000 possible (1.64% density)
  - 643 researchers (64.3%) have ZERO edges in training
    -> Cannot learn ANY embeddings from graph structure
    -> Embeddings for isolated researchers are random
    -> Model falls back to random feature-based matching

  - 44 researchers have only 1 edge (minimal training signal)
  - 357 researchers connected (only 35.7% of dataset)

MISSING GRAPH CONNECTIONS:
  - Institutions: Dataset is EMPTY (0 institutions)
    -> No institutional context
  - Co-author edges: MISSING
    -> Can't identify similar researchers through collaborations
  - Topic edges: Underutilized (303 grant-topic, 2,023 researcher-topic)
    -> Topic nodes report 0 connections (data quality issue)

RESULT: Majority of researchers have no graph information
        -> Model can't propagate information through structure
        -> Isolated researchers are classified by nearly-identical features

================================================================================
ROOT CAUSE #3: MODEL CAPACITY TOO SMALL [IMPACT: +15-20%]
================================================================================

ARCHITECTURE:
  - Hidden dimension: 64 (3x too small)
    -> 1,000 researchers → 64 dims = 15.6 bits per researcher
    -> 200 grants → 64 dims = 0.32 bits per grant
    -> Cannot capture nuanced differences between similar entities

  - HGTConv heads: 2 (should be 4+)
    -> Limited representational power
    -> Can't learn independent subspaces

  - Graph layers: 2 (should be 3-4)
    -> Information propagates only 2 hops
    -> In sparse graphs, most pairs are 3+ hops apart
    -> Message passing doesn't reach most researchers

  - LinkPredictor MLP: 128→64→1 (too simple)
    -> Only 3 layers
    -> Can only learn linear/simple patterns

RESULT: Model literally doesn't have capacity to learn complex patterns
        -> Even if features were good, architecture would bottleneck

================================================================================
ROOT CAUSE #4: LOSS FUNCTION TREATS ALL NEGATIVES EQUALLY [IMPACT: +10-15%]
================================================================================

CURRENT APPROACH:
  criterion = nn.BCELoss()
  loss = criterion(preds, labels)  # pos_preds vs neg_preds equally weighted

PROBLEM:
  - Random negative sampling is too easy to distinguish
    Example: Researcher (AI specialist) vs Grant (Climate grant) - obviously wrong
  - Model learns to classify but not to RANK correctly
  - No distinction between:
    * Hard negatives: Topically similar grant, different researcher
    * Easy negatives: Random unrelated grant
  - BCELoss doesn't care about ranking order
    -> Model can get low loss while ranking is terrible

RESULT: Good training loss but poor ranking performance
        -> Explains loss decreasing but hit rate staying at ~random

================================================================================
ROOT CAUSE #5: NEGATIVE SAMPLING IS POOR [IMPACT: +5-10% for hard negatives]
================================================================================

CURRENT APPROACH (lines 69-78 in train_gnn.py):
  while len(neg_src) < len(pos_src):
    candidate_src = torch.randint(0, num_r, (1,)).item()
    candidate_dst = torch.randint(0, num_g, (1,)).item()
    if (candidate_src, candidate_dst) not in pos_edge_set:
        neg_src.append(candidate_src)

PROBLEM:
  - Completely random sampling
  - Likely samples many irrelevant pairs that don't look like positives
  - No hard negative mining
  - Model never sees "similar grant, different researcher" examples
  - Training signal is weak because negatives aren't contrastive

RESULT: Model doesn't learn to discriminate between similar items
        -> Only learns to classify as positive/negative, not to rank

================================================================================
ROOT CAUSE #6: DATA QUALITY ISSUES [IMPACT: varies]
================================================================================

RESEARCHER DATA:
  - h_index: 52.1% are zero (unmeasurable)
  - Works_count: Some values suspiciously high (e.g., 1,898,731 works)
    -> Possible data entry error or misaligned schema
  - Very skewed distributions (h_index 0-321, citations 0-806K)

GRANT DATA:
  - Only varies on 1 meaningful feature (amount)
  - No meaningful grant descriptions in features
  - No career stage information (hardcoded to 2.0)

INSTITUTION DATA:
  - Completely empty (0 institutions) despite institution_id in researchers
  - Can't leverage institutional affiliation

TOPIC DATA:
  - All topics report 0 connections (grant_count=0, researcher_count=0)
  - But 303 grant-topic edges and 2,023 researcher-topic edges exist
  - Suggests data alignment issue
